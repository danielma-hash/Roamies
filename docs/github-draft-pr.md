# פתיחת טיוטת PR

`github_pr_prepare` מכין תצוגה של repo, remote, worktree, branches, שני SHA, כותרת וגוף. נדרשים branch ייעודי, commit שמור, עץ נקי ו־branch שכבר נדחף ל־GitHub. הכלי אינו עושה push או commit. ה־remote חייב להתאים ל־repo שנבחר; אין במסלול הזה PR בין repos שונים.

`github_pr_create` מקבל רק `previewId` שתוקפו חמש דקות. הוא מבקש אישור לתוכן וליעד המדויקים, ובודק שוב את ההרשאה, מצב ה־worktree, שני ה־SHA ומדיניות המפעל לאחר האישור. הוא יוצר `draft: true` בלבד וקורא את ה־PR חזרה מ־GitHub. `verified` מתייחס להתאמת תוכן/יעד של טיוטת PR פתוחה, לא לאיכות השינוי, CI או deploy.

יומן `sidekick/github-pr-intents.json` נשמר אטומית בהרשאות 0600 לפני POST. הוא כולל hashes ומצב, ללא גוף ה־PR. אחרי timeout מתבצעת קריאה בלבד לאיתור התוצאה. כוונה שעדיין אינה ניתנת לבירור נשארת `unknown` ומונעת POST חוזר, גם לאחר restart. PR קיים אינו נערך; אם תוכנו שונה, `contentMatches` ו־`verified` אינם מסומנים כהצלחה. עד 200 כוונות; אין מחיקה אוטומטית של תוצאות לא ידועות.

מדיניות המפעל נקראת בתהליך חדש מה־plugin המותקן בנתיב Codex המקומי. נבדקים `findProject`, הפרופילים המצורפים, רשימת ה־repos הגלובלית וכל ה־remotes. config חסר/לא תקין או remote לא מזוהה חוסמים את המסלול הכללי. פרויקט מנוהל מחייב `factory pr`; הכלים האלה אינם מחליפים את השער שלו ואינם מפעילים אותו. חיבור תהליך המפעל המלא הוא שלב נפרד.

אין כאן merge, deploy, push, עריכת PR קיים או הרשאה מתמשכת לכתיבה. כשל שמירת יומן חוסם כתיבה נוספת; סגירת חלון האישור מבטלת את האישור. הפרופיל מיועד לתהליך sidecar יחיד.
