# קריאת GitHub דרך Jarvis

משפחת `github` נטענת לפי דרישה. היא משתמשת ב־`gh` המקומי ובחיבור הקיים ל־github.com, לקריאה בלבד; היא אינה מעתיקה מפתחות ואינה מעניקה הרשאות חדשות.

- `github_pr_read`: כותרת, גוף מוגבל, מצב ו־head/base SHA.
- `github_issue_read`: issue נפרד, גוף מוגבל ותוויות.
- `github_pr_files`: עד 20 קבצים בעמוד; בלי תוכן patch.
- `github_pr_patch`: עד 6,000 תווים מקובץ אחד בעמוד שנבחר. `nextOffset` ממשיך את הקטע לאחר הסתרת סודות מוכרים.
- `github_pr_checks`: עד 20 check runs ו־20 status records בעמוד, על ה־commit שנבחר.

רשימות הקבצים, ה־patch והבדיקות דורשים את `expectedHead` ו־`expectedBase` מהקריאה הראשונה. שני ה־SHA נבדקים לפני ואחרי הקריאה; שינוי מחייב קריאת PR מחדש. זהו זיהוי שינוי בזמן הקריאה, לא נעילה אטומית של ה־repo.

כל קריאת API מוגבלת ל־15 שניות ול־1 MiB. מותרות רק כתובות issue/PR קנוניות, וה־endpoint מורכב בקוד עם `GET` בלבד. אין shell, endpoint חופשי, פקודת gh חופשית או כתיבה. תוכן חיצוני מסומן כנתונים לא מהימנים; שגיאות אינן הופכות לרשימות ריקות. שמות קבצים מוגנים, כולל מקור של rename, חוסמים החזרת patch.

יש להמשיך לפי `nextPage`. GitHub מגביל רשימת קבצים ל־3,000; חריגה מדווחת במפורש. קטע patch חסר/בינארי אינו הוכחה להעדר שינוי, וגם קטע שהוחזר אינו מוכיח שכל תוכן הקובץ נבדק. תוצאות CI ומצב PR אינם אימות deploy או אישור merge. מקור: [GitHub REST pull requests](https://docs.github.com/en/rest/pulls/pulls#list-pull-requests-files).

דוגמת בקשה: ״בדוק מה השתנה ב־PR הזה, קרא רק את הקבצים הרלוונטיים והראה אילו בדיקות רצו״. פתיחת PR, תגובות, merge ופעולות Monday אינם חלק ממחבר הקריאה הזה.
